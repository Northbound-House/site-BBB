# Bora Bora Bound

A static rebuild of [boraborabound.com](https://boraborabound.com) for hosting on **GitHub Pages**. Hand-coded HTML/CSS/JS — no build step, no dependencies.

> **Status: staging.** `CNAME` points at `test.boraborabound.com`, every page carries
> `noindex, nofollow`, and `robots.txt` disallows everything. This is deliberate — an
> indexable copy of the site on a second domain competes with the real one in search.
> Run `./tools/set-domain.sh production` to flip all of it at cutover.

Shared assets live in `assets/css/styles.css` and `assets/js/main.js`. The nav and
footer are repeated in each page (static site — no templating).

## `tools/` — the two scripts you need

Because there's no build step, page metadata would otherwise be duplicated across
seven files and drift. It doesn't: it's generated.

### `tools/build-head.py`

The single source of truth for every page's `<title>`, meta description, `robots`,
`rel=canonical`, Open Graph / Twitter tags, and JSON-LD structured data. It also
writes `sitemap.xml`, `robots.txt`, and the legacy redirect stubs.

```bash
python3 tools/build-head.py
```

Edit the `PAGES` table at the bottom of the script — never the `<head>` blocks in
the HTML directly, or the next run will overwrite you. Everything between
`<meta name="viewport">` and `<link rel="preconnect">` is generated; the rest of
each file is left alone.

### `tools/set-domain.sh`

Switches the whole site between staging and production in one command. The domain
appears in ~40 places (canonicals, `og:url`, `og:image`, sitemap, redirect stubs,
schema `@id`s) and they must stay in sync.

```bash
./tools/set-domain.sh staging      # test.boraborabound.com, noindex, robots Disallow
./tools/set-domain.sh production   # boraborabound.com, indexable, robots Allow + Sitemap
```

Running `production` also prints the cutover checklist for the steps a script can't
do (DNS, Search Console, Change of Address).

## Legacy URL redirects

The old Travefy site served extensionless URLs. This repo serves `.html` files, so
each old path gets a directory containing a redirect stub (canonical + instant meta
refresh, which Google treats as a permanent redirect):

| Old URL | Goes to |
| --- | --- |
| `/about` | `/about.html` |
| `/promise` | `/promise.html` |
| `/ourpromise` | `/promise.html` — indexed but dead since the original rename |
| `/testimonials` | `/testimonials.html` |
| `/refer` | `/refer.html` |

These are generated by `build-head.py` from the `LEGACY_REDIRECTS` map. Add a row
there if another old URL turns up in Search Console.

## Deploying to GitHub Pages

1. Push to the default branch.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   branch `main`, folder `/ (root)`.
3. **DNS.** Add an `ALIAS`/`ANAME`/flattened-`CNAME` on the apex → `<you>.github.io`,
   **or** four `A` records to GitHub's IPs: `185.199.108.153`, `185.199.109.153`,
   `185.199.110.153`, `185.199.111.153`. Add a `CNAME` for `www` → `<you>.github.io`.
4. **Settings → Pages**, confirm the custom domain and tick **Enforce HTTPS** once
   the cert is issued.

`.nojekyll` is included so GitHub serves the files as-is without Jekyll processing.

## A note on Review structured data

`testimonials.html` carries `Review` JSON-LD, but **it will not produce star ratings
in search results** — Google ignores self-serving review markup on an organisation's
own site. It's included because it still helps Google resolve the business as an
entity, which supports the Google Business Profile work. Deliberately no
`aggregateRating`: there's no verifiable rating data behind it.

## Swapping imagery

Hero/section photos are free Unsplash placeholders referenced inline via CSS custom
properties. Each has a gradient/colour fallback, so the design holds even if an image
fails to load. Replace the URLs with your own photos (ideally in `assets/img/`) when
ready.
